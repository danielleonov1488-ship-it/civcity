# Набор деталей римского форта

Генератор для Blender 4.5: девять самостоятельных GLB, один mesh на деталь,
два материала у деревянных конструкций и три у палаток. Геометрия создаётся
кодом, без загрузок. Образец — утверждённый `fort_concepts.jpg`; пропорции,
гранёное дерево и сдержанные детали рассчитаны на стиль Synty.

В рамках FORT-ART подготовлены скрипты. Blender и Godot не запускались:
GLB и `preview.png` появятся только после команд ниже.

## Запуск генератора

Из Git Bash, рабочая папка — **godot в lane g**, не основной проект:

```bash
cd /d/CivCity/.work/lanes/g/godot
bash /d/CivCity/tools/blender.sh -b --python-exit-code 1 -P setup/fort_kit/fort_kit.py
```

Эквивалентный вызов Blender напрямую:

```bash
blender.exe -b --python-exit-code 1 -P setup/fort_kit/fort_kit.py -- out=D:/CivCity/.work/lanes/g/godot/assets/fort
```

Папка по умолчанию определяется относительно скрипта: `godot/assets/fort/`.
Дополнительный параметр `textures=<dir>` меняет только место чтения текстур.
По умолчанию читаются оригинальные `Wood_01.png` и `Wood_02.png` из
`D:/CivCity/godot/assets/synty/Textures/Base/`. При отсутствии текстур генератор
завершится с ошибкой до записи моделей. Текстуры не изменяются и не копируются
отдельно; экспортёр встраивает их в GLB. Такие GLB содержат материалы Synty:
не добавлять их в публичный репозиторий.

Существующие GLB и `fort_manifest.json` сохраняются: при совпадении имён
генератор откажется от записи. Для следующего прохода задайте новую папку:

```bash
bash /d/CivCity/tools/blender.sh -b --python-exit-code 1 -P setup/fort_kit/fort_kit.py -- out=D:/CivCity/.work/stage3/fortart/pass02
```

Успех: девять строк `FORT EXPORT`, затем `FORT DONE`. Файл
`fort_manifest.json` содержит фактические границы и число треугольников после
фасок, материалы, seed и параметры конструкций. Ошибка Python возвращает
ненулевой код при использовании `--python-exit-code 1`.

## Детали и размеры

Размеры — ширина × глубина × высота, метры, в координатах Blender.
Для палаток указана тканевая часть: колышки и оттяжки выступают за неё.

| Файл | Основные размеры | Детали |
| --- | --- | --- |
| `palisade_seg.glb` | шаг 2,0; брёвна 3,3–3,9 | 8 брёвен Ø0,25, 8 граней, острия, наклон до 2°, внутренняя обвязка; seed 1729 |
| `palisade_seg_b.glb` | тот же шаг 2,0 | другой набор высот и наклонов; seed 2718 |
| `tower.glb` | около 3 × 3 × 9,1 | 4 стойки, X-раскосы на четырёх гранях каждого яруса, настилы на 4,1 и 7,85 м, перила с X-узором, внутренняя лестница и проёмы в настилах |
| `gate.glb` | проём 4,5; полный размер около 5,42 × 2,35 × 4,57 | две стойки, перемычка, дощатые створки с раскосами, открыты внутрь на 70° |
| `bridge.glb` | 3,5 × 6 × 1,43 | 30 досок, две нижние несущие балки, низкие перила; верх настила на 0,485 м |
| `tent_small.glb` | 2,6 × 3,2 × 2,2 | 2 стойки, открытые подвязанные пологи, красная кромка, оттяжки и колышки |
| `tent_long.glb` | 3,5 × 8 × 2,6 | 3 стойки, тот же рисунок ткани и креплений |
| `tent_command.glb` | 6 × 5 × 3,8 | короткий конёк 1,6 м, скатные торцы, красные полосы и фигурная кайма, открытый вход, знамя спереди |
| `stakes_row.glb` | около 2,92 × 0,37 × 0,96 | 10 заострённых кольев с 6 гранями, поперечная связь |

Полные границы с оттяжками до экспорта: малая палатка около 4,02 × 4,68 м,
длинная 4,92 × 9,48 м, командная 7,52 × 6,38 м. У наклонных круглых деталей
нижняя грань даёт поправку высоты в несколько миллиметров; минимум Z
нормализуется в ноль. Башня открыта сверху, крыши нет.

## Координаты и материалы

- 1 единица = 1 метр; Blender +Z вверх. Экспорт `export_yup=True`: Godot +Y вверх.
- Начало координат — центр основания конструкции на земле. Для ворот это
  центр проёма в линии стены; открытые створки не смещают начало координат.
- Входы смотрят в Blender −Y, после импорта в Godot +Z. Внутренняя сторона
  частокола и направление открывания ворот — Blender +Y / Godot −Z.
- Частокол стыкуется с шагом ровно 2 м по X. Наклон брёвен меняет глубину,
  сохраняя ширину модуля. Опоры моста стоят на Z=0; для моста над рвом
  размещать настил с учётом его высоты 0,485 м относительно origin.
- Геометрия плоско затенена. На деревянных частях применяются фаски 0,012 м,
  один сегмент, только на рёбрах с углом больше 60°. Трансформации применены.
- `Wood_01` используется на брёвнах/стойках, `Wood_02` — на досках и перилах.
  UV V идёт вдоль элемента, включая наклонные раскосы. Один повтор вдоль 2 м.
- Палатки: кремовый `#E9DCC0`, красный `#B23A2E`, верёвочный `#8A6A45`.
  Стойки и колышки палаток используют тот же простой коричневый материал,
  что и верёвки: всего три материала. Ткань двусторонняя, без прозрачности.
- Каждый GLB содержит один mesh с 2–3 material slots. Материальные примитивы
  внутри glTF не являются дополнительными mesh-объектами. Коллизии и
  интеграция в игровые сцены в этот набор не входят.

## Контактный лист Eevee

После генерации:

```bash
cd /d/CivCity/.work/lanes/g/godot
bash /d/CivCity/tools/blender.sh -b --python-exit-code 1 -P setup/fort_kit/preview.py
```

Скрипт импортирует **все `*.glb`** из папки, последовательно рендерит их
в Eevee с ракурсом три четверти, тёплым солнцем, мягкими тенями и светло-серой
землёй. Для штатных девяти моделей получается сетка 3 × 3, 1600 × 900.
Масштаб кадрирования для каждой детали отдельный; подписи показывают реальные
полные габариты, включая верёвки и створки.

Результат: `D:/CivCity/.work/stage3/fortart/preview.png`.
Отдельные кадры сохраняются рядом в `preview_tiles/` и не удаляются.
PNG собирается стандартной библиотекой Python без повторного применения AgX.
Для другого набора или повторного рендера:

```bash
bash /d/CivCity/tools/blender.sh -b --python-exit-code 1 -P setup/fort_kit/preview.py -- in=D:/CivCity/.work/stage3/fortart/pass02 out=D:/CivCity/.work/stage3/fortart/preview02.png
```

Превью тоже не перезаписывает существующие файлы. Успех: `FORT PREVIEW TILE`
для каждой детали, затем `FORT PREVIEW DONE`.

## Проверка без Blender

```bash
cd /d/CivCity/.work/lanes/g/godot
python -B setup/fort_kit/fort_kit.py --check
```

Проверяет состав набора, материалы, конечные координаты, ненулевую площадь
граней, UV, нижнюю отметку, число треугольников, ширину секций, наклон брёвен,
воспроизводимость seed, размер моста и проём ворот. Файлов не записывает,
`bpy` не импортирует. После реального экспорта дополнительно проверить:

1. В manifest девять моделей, по одному mesh и не более трёх материалов.
2. В превью нет пропавших текстур, чёрных граней, обрезанных деталей; ткань
   видна изнутри, двери открыты внутрь, верх башни открыт, доски имеют фаски.
3. В Godot при разрешённой интеграционной проверке: размер в метрах, origin
   на земле, направление входа +Z и шаг частокола ровно 2 м.

Реальный экспорт, рендер и проверка импорта намеренно оставлены для разрешённого
запуска владельцем процесса. Эта задача не изменяет `godot/scripts/`.
