# Как выпустить CivCity

Все команды запускаются в Git Bash из папки `D:\CivCity`. Всё, что они пишут, остаётся на диске D.

## Ключ подписи — беречь

Лаунчер запускает скачанную игру, поэтому опись игры (`game/manifest.json`) подписана ключом владельца:
`secrets/manifest_ed25519.pem` (в git его нет, на сервер он не попадает). Его открытая половина вписана в лаунчер
(`desktop/updater.js`, `PUBKEY_B64`). Без ключа `deploy.sh` игру не выложит, а опись с чужой подписью лаунчер не примет.

- Держите копию ключа на флешке или в другом надёжном месте. Потерянный ключ означает новый лаунчер с новым ключом:
  всем игрокам придётся заново скачать установщик.
- Другой путь к ключу: `CIVCITY_SIGN_KEY=путь bash deploy/deploy.sh …`.

## Обычное обновление игры

Код, интерфейс или модели поменялись, а лаунчер остался прежним.

1. **Собрать игру:** `bash tools/build_game.sh`. Сборка появится в `build/game`, номер сборки каждый раз растёт на 1.
2. **Выложить:** `bash deploy/deploy.sh game`. На сервер уйдут только изменившиеся файлы, обычно около 1 МБ.

Лаунчеры игроков скачают обновление при следующем нажатии «Играть».

**Если в выпуске поменялся и сервер (`server/`), сначала выложите его:** `bash deploy/deploy.sh server`, и только потом
`bash deploy/deploy.sh game`. Новая игра рассчитывает на новые адреса сервера. Пример — название города (сборка после 20):
игра меняет его через `PUT /api/pvp/name`, а совет «Дайте городу имя» показывает, только когда сервер сообщает
`rename: true`. Со старым сервером переименовать город без Легиона нельзя.

## Полный выпуск (как 1.0)

1. **Собрать игру:** `bash tools/build_game.sh`.
2. **Собрать установщик лаунчера:** `bash deploy/build_launcher.sh` (около минуты). Получится `desktop/dist/CivCity-<версия>-setup.exe`, версия берётся из `desktop/package.json`.
3. **Проверить сайт:** в папке `site/` должен лежать новый сайт, начиная с `site/index.html`. Кнопка «Скачать» на сайте должна вести на `/download/CivCity-setup.exe`. Видео и снимки сайта (`site/media/`, около 80 МБ, в git не хранятся) собирает `python -I deploy/build_site_media.py` (всё или по частям: `art fonts hero loops screens trailer credits`). Посмотреть сайт у себя: `node deploy/local_site.js --port=8090 --site=site --api=http://127.0.0.1:3010`.
4. **Обновить новости лаунчера:** они лежат в `server/launcher.json` (дата, заголовок, текст).
5. **Проверить у себя, ничего не отправляя:** `bash deploy/deploy.sh check`.
6. **Выложить всё:** `bash deploy/deploy.sh`.

Шаг 6 отправляет на сервер:

- игру для лаунчера (`/srv/civcity/game`);
- установщик (`/download/CivCity-setup.exe`);
- сайт вместо старой браузерной игры (папка `/download/` сохраняется);
- сервер аккаунтов и Caddy.

В конце скрипт сам проверяет `https://civcity.ru`. Если всё в порядке, он пишет «выложено». Код выхода:

- `0` — выложено и проверено;
- `1` — выкладка оборвалась (ошибка, сервер аккаунтов не поднялся после перезапуска и т. п.);
- `2` — файлы ушли, но проверка снаружи нашла неполадки (см. «ВНИМАНИЕ» в выводе).

Сервер аккаунтов едет вместе со своими зависимостями (`server/node_modules`): на сервере npm нет. На новом компьютере
(или после чистого клонирования) сначала выполните `cd server && npm ci --omit=dev`. Без этого шаг `server` остановится
с подсказкой.

**Первый раз с 1.0.** Шаг 6 обязательно должен выложить и `server`: только новый `Caddyfile` открывает адрес `/game/`. Старые лаунчеры 0.9 прочитают `game-manifest.json`, покажут «Вышла новая версия программы» и кнопку «Скачать». После установки 1.0 вход сохранится.

Чтобы выложить только часть, перечислите нужное: `bash deploy/deploy.sh site`, `… game installer` и так далее. Можно: `site`, `game`, `installer`, `server`.

## Если что-то пошло не так

- **Откатить игру на прежнюю сборку:** `bash deploy/deploy.sh rollback 12`, где 12 — номер сборки. На сервере хранятся пять последних. Лаунчеры вернутся на неё при следующем «Играть». Сборку старее установленной лаунчер сам не ставит, поэтому откат переподписывает прежнюю опись у вас с пометкой `"rollback": true` (нужен ключ подписи).
- **Игрок жалуется, что игра не запускается.** Пусть нажмёт «Проверить файлы игры» в лаунчере. Журналы лежат здесь:
  - лаунчер: `%APPDATA%\CivCity\launcher.log`;
  - игра: `%APPDATA%\CivCity Game\logs\godot.log`.

## Проверить сервер до выкладки

```
node server/test.js
node server/test_pvp.js
```

Первая проверка — аккаунты и сохранения в облаке, вторая — бои с городами (Легион). Обе запускают свой сервер со своей папкой данных в `.work` и в конце пишут «ALL OK».

Победы в боях с городами сервер не принимает на слово: он повторяет бой сам (`server/legion_sim.js` — точная копия
`godot/scripts/legion_sim.gd`). Если меняли бой (`legion_sim.gd`) или числа бойцов и умений (`legion.gd`), поменяйте
то же в `server/legion_sim.js` и сверьте их до бита:

```
tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path godot --script res://scripts/test_sim_dump.gd -- n=1000 out=D:/CivCity/.work/sim_dump.json
node server/test_sim.js D:/CivCity/.work/sim_dump.json
```

Должно быть «ALL OK». Если бои разошлись, честные победы игроков сервер будет отклонять.

## Игра против живого сервера

Все проверки выше ходят на свой сервер по простому http. Эта — на настоящий https://civcity.ru через тот же код, что у игры (`godot/scripts/net_http.gd`), и только читает: здоровье сервера, `/api/launcher` (большой ответ приходит сжатым и кусками) со сжатием и без, таблицу лучших без входа (ждём 401).

```
bash tools/godot.sh --headless --path godot --script res://scripts/test_live_net.gd
```

Должно быть «LIVE DONE fails=0». Запускайте с включённым VPN и без него. Если сбой, строка покажет его вид: `dns` (имя не нашлось), `connect` (нет соединения), `tls` (защищённое соединение), `timeout` (долго нет ответа), `read` (ответ не прочитался). В игре те же сбои пишутся в `godot.log` строками «NET …».

## Проверить собранную игру у себя до выкладки (без человека)

Тестовые сцены в сборку не попадают, поэтому в игре есть автопроверка `--qa` (`godot/scripts/qa_drive.gd`). Без этого аргумента она ничего не делает.

```
PORT=3010 DATA_DIR=D:/CivCity/.work/srvdata node server/index.js     # в отдельном окне
bash .work/py/gpu_run.sh res://test_qa_city.tscn                       # город с Легионом для облака
node deploy/qa_accounts.js                                             # тестовые аккаунты на своём сервере
bash deploy/qa_exported.sh all
```

Три проверки собранной игры (`build/game`), каждая под замком видеокарты:

- `login`: окно входа, регистрация, «Играть», новый город, сохранение в облако, выход;
- `restore`: вход на «чистом компьютере», город скачан из облака;
- `legion`: вход как от лаунчера, окно «Легион», 3D-бой, итог, «Против городов».

В конце скрипт пишет «ВСЁ В ПОРЯДКЕ». Снимки лежат в `.work/qa/shots/`.

**Значок игры.** Значок `CivCity.exe` (`godot/assets/ui/ai/app_icon.png`, из картинки владельца `30.png`) и строки свойств файла в `godot/export_presets.cfg` после выхода 1.0 лучше не менять. Любая такая правка меняет `CivCity.exe`, и каждый игрок заново скачает около 28 МБ.

## Проверить лаунчер у себя до выкладки

```
bash deploy/deploy.sh check
PORT=3010 DATA_DIR=D:/CivCity/.work/srvdata node server/index.js
node deploy/local_site.js --port=8090 --api=http://127.0.0.1:3010
```

Вторая и третья команды — сервер аккаунтов и сайт с игрой. Запустите каждую в отдельном окне.

Затем запустите лаунчер (`desktop/dist/win-unpacked/CivCity.exe`) с такими переменными окружения:

- `CIVCITY_USERDATA=D:/CivCity/.work/launcher_test/userdata`
- `CIVCITY_UPDATE_URL=http://127.0.0.1:8090/`
- `CIVCITY_API=http://127.0.0.1:8090/api`
- `APPDATA=D:\CivCity\.work\launcher_test\appdata`, чтобы игра не писала на диск C.

Запускать лаунчер нужно под замком видеокарты: `mkdir D:/CivCity/.work/gpu.lock`, после проверки `rmdir`.

Для проверок без человека есть ещё три переменные:

- `CIVCITY_SMOKE=1`: лаунчер сам нажимает «Играть» и выходит, когда игра закроется;
- `CIVCITY_SMOKE_CLOSE=30`: закрыть игру через 30 секунд;
- `CIVCITY_SHOTS=папка`: снимки окна лаунчера.

## Что где

| Что | Где |
|---|---|
| Сборка игры | `deploy/build_game.sh` → `build/game` (exe, наборы `.pck`, `version.json`) |
| Опись игры для лаунчера | `deploy/game_manifest.js` → `.work/deploy/game` (подписанный `manifest.json`, файлы `f/<sha256>` и `f/<zsha>.zst`) |
| Ключ подписи описи | `secrets/manifest_ed25519.pem` (не в git, не на сервере — беречь копию) |
| Лаунчер | `desktop/` (`main.js` — окно и запуск игры, `updater.js` — загрузка и обновление игры) |
| Выкладка | `deploy/deploy.sh`; настройки веб-сервера — `deploy/Caddyfile` |
